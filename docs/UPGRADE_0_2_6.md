## 数据库兼容

本次完整候选共 **297 条 SQL**：生产已应用的 291 条保持文件名与校验和不变，新增 5 条上游迁移及 1 条兼容迁移。

上游 235/236 会把 `groups.models_list_config` 改为 `model_allowlist`。直接执行会使旧镜像的查询失败，因此新增 `234z_group_model_allowlist_compatibility.sql`，在上游迁移前保留两列并同步。旧版或新版只写其中一列时，触发器同步另一列；并发写入由行锁串行化。已有非空冲突值或同一语句写入不一致值时拒绝覆盖，避免默默丢配置。JSON `null` 与 SQL `NULL` 不混淆。

迁移执行器按完整文件名排序并逐项查已执行记录，因此新 `234z` 会在 235 前执行，即使生产已有其他较大编号的二开迁移。原有 10 条二开 SQL 字节未变。

真实 PostgreSQL 回归使用生产的 291 条文件名/校验和清单，从空库执行原迁移，植入合成余额、套餐、账本、待结算回执、支付及绑定，再执行完整 297 条。检查历史迁移时间戳与账务指纹不变、旧版迁移启动和新版重放幂等，并验证旧/新列读写与并发写入。上游 238 按其设计删除“所有上限均为空”的平台额度行；有显式额度的行必须保留。

## 新票据功能

默认 `openai_codex_ticket_enabled=false`。关闭时采集、注入和 fail-closed 门禁都不执行；管理端开关和采集代理配置实时生效，代理认证部分按上游规则掩码返回。

启用时沿用上游默认 `fail_closed=true`：适用的 OAuth 模型没有可用票据时会拒绝请求，而不是无票继续转发。应先验证采集代理、票据缓存及目标账号，再小范围启用。此次使用模拟测试及无 OAuth 账号的本地设置验收，不采集真实生产票据，也不把 292 位格式检查当成模型身份或质量证明。
