# 提示词风控迭代需求

日期：2026-09-08。状态：设计提案，待评审；不表示已实现、已启用或已部署。

## 目标

在请求进入业务上游前，识别并拒绝命中平台禁止规则的文本提示词；管理员能根据请求查到当时的真实用户、具体文本、判定依据与处置结果，并发现重复尝试和审核系统故障。

核心价值是减少有害请求到达业务上游，同时保留可复核证据。内容分类和越狱检测均为判断信号，不能承诺覆盖 OpenAI 全部条款、零漏检或上游账号绝不受限。

## 已确认的事实

- 用户已授权研究和设计迭代方案。本轮不修改业务代码，不调用真实审核模型，不修改线上配置。
- 已存在 OpenAI Moderation、Qwen3Guard、同步/异步模式、事件数据库、管理页面和运行指标，优先复用。
- 同步记录失败可丢事件；旧 Moderation 故障放行；现有完整文本字段丢失角色和原顺序，且最多 65536 字符。
- Qwen3Guard 的 0/0.5/1 是本地等级映射，不是模型置信度；其类别也不等于 OpenAI 使用政策。
- 证据与源码定位统一见 [研究基线](research/baseline.md)，历史 OpenSpec 不能替代当前源码事实。

## 本版建议的产品规则

这些数值和处置是供本次评审的明确提案，实施前需确认整体方案；不从当前默认配置推断用户已经接受这些行为。

| 情形 | 当次请求 | 记录与计数 |
| --- | --- | --- |
| 命中已启用、已校准的内容禁止规则 | 同步拒绝 | `policy_blocked`，保留具体规则依据，单独累计内容命中数 |
| 命中已校准的主动绕过安全限制规则 | 同步拒绝 | `attack_blocked`，属于站内安全规则，不笼统宣称违反 OpenAI 全部条款 |
| 仅疑似攻击、Controversial、引用语境不明确 | 放行并待复核 | `suspicious`，不累计为确认违规，不自动处罚 |
| 正常编程、授权逆向、安全研究、求助、修改上一条需求 | 放行 | 不累计违规；通过请求原文在审核完成后清除 |
| 必需审核引擎超时、无配置、返回格式非法、存储不可用 | 暂不可用，不转发业务上游 | `system_error`，不累计用户违规 |
| 无可检查文本或历史/附件不在请求中 | 显式标记覆盖范围 | 不得记成“全部内容审核通过”；严格文本入口没有文本时拒绝并提示不支持的输入 |

默认不新增自动封号、扣费、自动永久黑名单或逐请求人工审批。管理员复核不会重放原请求，也不会自动放行该用户后续请求。

## 范围

首期覆盖指定分组中现有已接线入口的客户端可控文本：Chat、Responses HTTP/SSE/WebSocket 每轮、Claude、Gemini、图片/媒体生成的文本提示词。审核范围是当前请求携带、将供模型读取的文本，包含 system/developer/user/assistant/tool 内容以及工具参数、工具返回、工具说明和输出格式中的文本说明。按设计中的字段矩阵补齐现有提取器；角色字段也来自客户端，不赋予其绕过审核的权限。

只选择少量明确分组开始灰度。其他分组与原审核模式继续保持已有契约；升级不得自动开启全站强制审核。

图片像素、音频、附件二进制、远程 URL 内容、未提供的历史、模型输出不在首期识别范围。媒体请求即使文本通过也应显示 `text_only`，不能显示多模态完整审核。

## 需求与验收

| ID | 需求 | 可观察的验收结果 |
| --- | --- | --- |
| R01 | 版本化规则，分离模型信号与平台处置 | 事件能查规则、策略版本、模型标识、等级/分数类型；Controversial 不再因固定 0.5 被当作概率阈值 |
| R02 | 先审核后转发 | 明确阻断/审核故障时，账号调度、扣费、业务上游调用、媒体任务创建等适用计数全部为零；SSE 无提前成功首字节 |
| R03 | 可信且稳定的身份 | 用户名来自鉴权上下文；请求体伪造 user/username 无效；改名/删用户后仍保留原用户 ID 快照和当时名称 |
| R04 | 可恢复的留痕 | 首次持久接纳成功后，恢复窗口内尚未完成的输入不因进程退出、客户端断开、多实例重试丢失；原请求判定与恢复结果分开，最终请求事件不重复 |
| R05 | 具体提示词可复核 | 原文本、角色、顺序、来源路径可查看；模型提供命中位置时可定位，否则明确不可用；超出明确上限时拒绝，不能静默截断后标记完整 |
| R06 | 原文受控查看与清理 | 普通列表/详情不返回原文；只有管理员通过单独读取接口查看，读取审计持久化成功才返回；过期、删除、解密失败可区分 |
| R07 | 监控与重复尝试可见 | 按用户、类别、时间、规则查询；疑似、阻断、已确认、误判和系统故障分列；同一次审计不会重复计数 |
| R08 | 复核闭环 | 管理员可标记待复核/确认命中/误判/无法判定，带操作者和理由；修改冲突返回 409；复核不改写原模型判定 |
| R09 | 协议和兼容性 | HTTP/SSE/WS 首轮及后续轮次均验证；现有错误 envelope 保持兼容；未启用新 profile 的业务请求决策无变化，管理读取与加密另按全局证据保护步骤迁移 |
| R10 | 有效性可证明 | 冻结盲测集、报告中英文误拦和召回、延迟与容量；模拟接口通过不能算真实模型效果通过 |

R04 的承诺边界：数据库首次提交失败时，只能保证不转发，无法保证该请求原文已保存。持久介质整体损坏依赖备份恢复。模型已返回但判定未提交即崩溃时，只能重新审核已保存输入，不能伪称找回原判定。

## 留存与告警建议值

| 数据/事件 | 提案 |
| --- | --- |
| 同步审核中的原文 | 加密暂存；正常通过后在完成事务内删除 |
| 内容阻断、攻击阻断、疑似待复核原文 | 自首次接纳起 30 天；管理员删除后不再授权新的读取，已授权在途读取不承诺撤回 |
| 未完成/系统故障的原文 | 自首次接纳起最长 24 小时；窗口内恢复发现风险则转为 30 天；到期标记不可恢复并删除原文 |
| 风险事件、复核及原文访问元数据 | 180 天；不包含原文或密钥 |
| 正常通过任务元数据 | 24 小时，供幂等和恢复核对；不产生长期通过事件 |
| 重复尝试告警 | 同用户 10 分钟内至少 5 次独立阻断；30 分钟内合并，显示累计次数 |
| 系统故障告警 | 提交失败/密钥不可用立即输出不含原文的运行信号；存储可用时持久告警。5 分钟内审核失败率超过 1% 且至少 5 次失败触发运行告警；不承诺数据库完全宕机时站内告警仍可持久化 |

首期“监控”指现有后台中的运行状态和风险事件。第二阶段补站内持久告警与复核；外部邮件/Webhook 为可选通道，默认关闭，后续配置收件人后启用。本轮不发送任何通知。

## 分期与非目标

交付顺序为 P0 策略/样本基线、P1 同步阻断与可靠证据、P2 监控复核、P3 真实模型与灰度验收；完整需求验收包括 P2 和 P3，不把 P1 当成全部完成。

本版不新增 NeMo 等编排框架，不替换网关，不更改拼车/额度等无关业务。不开发多模态识别、模型输出审核、自动处罚、申诉门户或通用角色权限系统。具体技术契约见 [设计](design.md)，执行与验收见 [实施清单](implement.md)。
