# I2 — Manual quota terms, durable operations and current-card reads

Based on I1 commit `92bd96e6feaa4426bacb2312eed8e2d162ba1bc7`, in the isolated `codex/claude-weekly-quota` worktree. No production card, model call, migration, configuration change or deployment was performed. I3 generation and billing remain disabled.

## Implemented boundary

- Added the shared exact-decimal domain model and service/repository ports. The OpenAPI lexical pattern rejects missing/empty/zero/negative/nonfinite/scientific amounts, leading zeros, overprecision and values outside NUMERIC(20,8). Accepted inputs normalize to eight fractional digits without rounding requested allowances. Public monetary projections are strings; no binary float enters these operations.
- Manual preview is a repeatable-read, read-only transaction: no parent, term, operation or outbox is created. Selected plans must belong to the target group, have a positive exact default and a seven-day duration; manual selection does not require `for_sale`. Explicit quota takes precedence and its override source is recorded. Snapshot names/default/update time are frozen on the term.
- Open/renew uses a user/group advisory transaction lock, checks successful operations before current state, then locks the parent, ordered terms by ID and late user/group/actor entities. It samples `clock_timestamp()` after lock waits. New issuance checks the separate issue/group gate after replay. Mutations require the parent revision; ordinary usage never increments it. New cards last exactly 168 hours. Renew appends after the uncancelled tail or the current database time, and does not carry quota or activate a future card early.
- Durable operation scope includes action, actor, target user and group (cancellation also names its target term). It stores normalized intent, original resolved source snapshot, fingerprint and original public result in the same transaction as the rights change. Replay is checked before today's plan/default, schedule, revision and issue gate. Changed intent conflicts; edited/deleted plans cannot invalidate the successful original result. The operation does not use GPT billing fingerprint/receipt codecs.
- Cancellation preserves immutable original time/allowance/used fields. It increments schedule revision, marks closing when unresolved requests exist and otherwise closed, without refunding, moving a future card, deleting a parent or touching a ledger. Parent starts remains the earliest historical start; expires follows the latest uncancelled card, or retains the historical endpoint if all are cancelled. A subsequent new open cannot inherit a cancelled tail's distant expiry.
- User summaries, history, settled usage and current-term entitlement use the dedicated repository. Reads use a consistent transaction snapshot; the current-term SQL predicate uses a single materialized DB clock and half-open interval. Parent expiry, permanent allowed groups and future-only schedules never grant current entitlement. Exhausted current cards may retain Key-management visibility. Unknown/pending requests remain distinct from zero cost.
- `last_term` selects the most recent actual end, using the earlier of cancellation and original expiry, with an ID tie-breaker. Scheduled/expired/cancelled public remaining is zero; historical unused allowance is still explained by quota minus actual used, and actual used is never cleared.
- All rights mutations atomically enqueue hashed Key invalidations in the existing auth outbox. The existing worker/subscriber provides delivery and retries. No new worker or network request occurs in the rights transaction. No balance, frozen balance, GPT term/cycle/ledger, old window usage or Key/account counters are written.
- Added actual admin/user HTTP routes, strict DTO decoding, explicit public response mapping, actor/ownership checks and 201-new/200-replay behavior. Key creation/rebinding/availability/visibility uses the current-term read port; startup Wire injects it into APIKeyService and AdminService. Missing/erroring readers fail closed for term candidates; pure GPT paths do not call the new read port. The HTTP/Key owner's exact evidence is in `I2-http-key-receipt.md`.
- Existing group deletion now refuses term groups at the repository sink. Cascade reads mode while holding only the group lock and exits before any parent access, avoiding the reverse group-to-parent lock order. Direct deletion has a final windows-mode SQL predicate and returns an explicit unsupported error for a protected term. Empty term groups are also protected; these group-deletion entries cannot soft-delete their parents.
