## Existing gaps that acceptance must reject

1. Historical `scripts/deploy.sh:64-72` stops the old application even if its 900-second wait expires. It also treats a failed `docker exec ... ps` as absence of old workers. A deadline or inspection error must leave both processes running, report incomplete drain, and preserve routing state.
2. Historical `scripts/switch-slot.sh:28-38` treats a successful reload command plus generic health probes as proof of target routing. Reload is asynchronous; old workers may answer briefly. Require fresh connections through both virtual hosts, actual target upstream identity, and committed route/active-slot agreement. A readiness probe returning 401 cannot identify which healthy application answered.
3. Historical `common.sh` hardcodes port 8080, one public host, and BWH layout. `bootstrap.sh` assumes container `sub2api` and changes one matching 8080 route. These are incompatible with the observed two-host `sub2api2` layout.
4. The historical Compose disables `CARPOOL_BACKGROUND_ENABLED` in both slots although the current application enables it. Preserve required GPT recovery/cycle maintenance across retirement; independently configure and verify Claude recovery. A pending durable receipt must not be stranded by disabling workers on the final serving slot.
5. `release/status.pending_usage` counts the process's usage worker pool, not every durable recovery worker. Combine HTTP/WS/usage drain status with exact synthetic receipt/ledger evidence and appropriate worker ownership semantics. Do not treat a zero counter as proof that all recovery receipts have settled.
6. The application uses a five-second HTTP `Shutdown`; upgraded WebSockets are outside Go's automatic shutdown wait. Stop only after natural HTTP/WS and usage completion. A long-lived idle WS can legitimately keep the old slot alive beyond the release command's budget.
7. Starting a new application must preserve the old process's Redis account/user slots and GPT WS ingress lease. The old prefix-deletion startup cleanup is a blocker until the backend fix is included in the tested candidate.

## Nginx and process boundaries

Nginx reload creates new workers and lets old workers finish their clients; `nginx -s reload` returning zero is not evidence those old workers have exited. Record the pre-reload worker identities and wait for that generation, avoiding an immediate `ps` race. A configured `worker_shutdown_timeout` closes remaining connections after its deadline, so an uninterrupted-release claim must account for the effective production setting. [Nginx reload semantics](https://nginx.org/en/docs/control.html), [worker shutdown timeout](https://nginx.org/en/docs/ngx_core_module.html#worker_shutdown_timeout).

WebSocket upgrade headers and proxy idle timers apply independently of routing. Test idle WS between turns as well as an active turn; a session can outlive all currently running model calls. Do not force-close it to make a drain test pass. [Nginx WebSocket proxying](https://nginx.org/en/docs/http/websocket.html).

Go `Server.Shutdown` does not wait for hijacked WebSocket connections. The existing release middleware counts the whole handler lifetime, including WS; use that independent evidence before container stop. [Go shutdown contract](https://pkg.go.dev/net/http#Server.Shutdown).

Recovery workers may overlap during release. Claude has durable leases and GPT applies idempotent billing receipts; exercise real competing recovery against a controlled known receipt and verify one debit. Never synthesize a PASS by clearing pending rows, rewriting admitted usage to settled, reducing deadlines, or disabling all recovery workers.
